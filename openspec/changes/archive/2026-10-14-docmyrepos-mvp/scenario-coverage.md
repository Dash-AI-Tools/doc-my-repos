# Scenario coverage (task 14.4)

Every `#### Scenario:` in `specs/*/spec.md` of this change, the test that exercises it, and the manual check for what needs a real GitHub App, a real pull request or a fresh machine. This file is not a spec: `openspec validate` ignores it. The `specs/` files are the source of truth; update this file when a scenario or a test changes.

How to read it:

- **automated** means a test asserts the scenario's THEN clause. Unit and database tests live next to the code (`src/**/*.test.ts(x)`, `tests/unit/`); the database tests use a real Postgres (`createTestDatabase`) and the sync tests talk to `FakeGitHub`, a fixture-backed fake of the GitHub REST API. Browser tests are Playwright specs in `e2e/` against the seeded stack (`e2e/support/seed-data.ts`).
- **manual** means the THEN clause needs something automation cannot provide here (a real GitHub organization, a real pull request, a clean machine with Docker). A static test guards what can be guarded, and the numbered check under "Manual checks" says what to do and what to expect.
- A test is cited as `file::test name` (nested `describe` names are included when they add meaning).
- "Real GitHub pass" in the notes points to the manual check that repeats an automated scenario against real GitHub. Those passes belong to tasks 14.1 and 14.2; they are not needed for the scenario to count as covered.

## Spec drift

The wording of these scenarios no longer matches what is implemented, or the implementation has behavior the specs do not mention. The specs were not edited. Recommended wording for the maintainer's `/opsx:update`:

1. **Inaccessible configured repository** (config-and-sources "Listed repository not accessible", github-sync "Inaccessible repository"). Implementation: a configured repository that the installation cannot see is reported in the sync run as "not accessible by the GitHub App" (an entry without a repository row, GitHub id 0). A previously synced copy is removed on the next complete listing (reason `not_in_installation`), not shown as errored. Recommended: _WHEN the config lists a repository that the installation cannot access THEN the sync run records "not accessible by the GitHub App" for it, a previously synced copy of it is removed, and other repositories are unaffected_. Keep "marked as errored" only for repositories that are still accessible but failed to sync.
2. **Sync status and run counts** (no spec). `/status` and `/api/status` show the latest run, per-repository state and warnings. Run counts include only repositories visible under the visibility rule (fail closed), so a hidden repository's results never leak. Recommended: a requirement "Sync status visibility" with scenarios "Errored repository shows its error and the last successful sync" and "Counts exclude repositories the viewer may not see".
3. **Document cap removes stored documents** (github-sync "Oversized or irrelevant files"). `limits.maxDocsPerRepo` (default 2000) keeps the first N documents by path; documents beyond the cap are not stored, earlier extra rows are removed, and a `docs_capped` warning is shown. Recommended scenario: _WHEN a repository has more Markdown files than the configured limit THEN only the first N by path are stored, the rest are removed and a visible warning says how many were left out_. Also document `limits.maxFileBytes` (default 256 KB, range 1 KB to 256 KB) in the "Oversized" scenario.
4. **Archived repositories are removed** (config-and-sources "Exclusions", github-sync "Repository removed from the installation"). A stored repository that becomes archived is removed (reason `archived`), by the `repository` event or the next sync, and returns when unarchived. Recommended scenario: _WHEN a synced repository is archived THEN it and its documents are removed from the app until it is unarchived_.
5. **Case-variant addresses redirect** (repo-space "Repository space page", "Document page navigation"). `/Acme/API-Service` and differently cased document paths redirect to the stored spelling; an ambiguous case-insensitive match is not guessed. Recommended scenario: _WHEN a visitor opens an address whose owner, repository or document path differs only in case THEN they are redirected to the canonical address_.
6. **Weak shared secret** (config-and-sources). The scenario exists (added in task 6.2). Since commit `84c0041` the startup check also rejects the `replace-with-...` placeholder values that `.env.example` ships, with a message that does not echo the value (`src/server/config/placeholder-secrets.test.ts`). Recommended: _WHEN the webhook secret or the sync secret is shorter than 16 characters after trimming whitespace, or is still the `replace-with-` placeholder from the example environment file THEN startup fails with an error that names the variable and does not print the value_.
7. **Mermaid limits** (markdown-rendering "Mermaid diagrams"). Diagrams never make network requests: HTML labels are off (HTML in a label shows as literal text), image shapes (`A@{img:...}`) are rejected before rendering, `%%{init}%%` cannot reopen `htmlLabels`, `flowchart`, `class`, `themeCSS` or font settings, and a diagram over 50 KB or beyond the 20th in a document stays a plain code block with a warning. Recommended scenarios: _Diagram with an external image reference renders without any network request_ and _Oversized or excess diagram is shown as code_.
8. **OKF notices and the metadata card only for OKF documents** (okf-support "Metadata card"). The card and the draft, deprecated and stale notices appear only on documents of OKF repositories, and never on `index.md` or `log.md`. A `status: deprecated` document in a plain Markdown repository shows no notice. Recommended: add to the requirement text "…on each non-reserved document of an OKF repository" and add the scenario _Plain repository with a status key shows no notice_.
9. **Table of contents order** (repo-space "Docs table of contents"). The text says "ordered by folder then title"; the implementation orders each folder as `index.md`, then documents by title, then subfolders by name, with `log.md` last. Recommended: state that order explicitly.
10. **Search is not stemmed and is bounded** (search "Full-text search"). The text-search configuration is `simple`: "deploy" does not match "deployment". Browsable depth is capped at 1000 results per query. Recommended scenarios: _Words are matched as written, without stemming_ and _Paging stops at the browsable limit with a message_.
11. **Configuration keys not in the spec** (config-and-sources). `defaults.docsPaths`, `limits.maxDocsPerRepo`, `limits.maxFileBytes`, `sync.intervalMinutes` (0 or 5 to 10080, default 60), `sync.onStartup` (default true), and the environment variables `SYNC_SCHEDULER`, `LOG_LEVEL`, `CONFIG_PATH`. Recommended: list them in "Config file narrows the repositories shown" or a new "Sync schedule and limits" requirement, with a scenario for the periodic and startup sync.
12. **Operational requirements not in any spec.** Security headers and the nonce-based CSP, the structured JSON logging with secret redaction, the scheduler with a cluster lock, the `/api/status` health endpoint, and `/api/asset` limits (type check by magic bytes, size cap, concurrency gate). They are tested (`src/proxy.test.ts`, `e2e/security-headers.spec.ts`, `src/server/log-sentinel.test.ts`, `src/server/assets/*.test.ts`) but have no scenarios. Recommended: a new capability "operations" or additions to markdown-rendering, with one scenario per behavior.
13. **Manual sync responses.** The sync endpoint accepts `Authorization: Bearer` only, answers 202 when the request was coalesced into a running sync, 409 for a never-synced repository that is busy, and 503 with `Retry-After` when rate limited. Recommended: extend "Authorized manual sync" with these outcomes.
14. **Stack names.** `CLAUDE.md` and `design.md` still name `@octokit/rest` and `@octokit/webhooks`; the code uses a small `fetch` client and `node:crypto` for signatures. Not a scenario, but update both documents.
